# Что такое **ClearBox**？

**ClearBox** — это многофункциональный, глубокий и быстрый инструмент-«коробка» для очистки, который позволяет одним нажатием освободить место на устройстве, упорядочить и заблокировать хранилище, удалить кэш приложений, установочные пакеты, архивы, мусор, пустые папки, а также подавить создание кэша, классифицировать и очищать файлы, блокировать обновления и установку приложений. Поддерживаются пользовательские правила очистки, классификации файлов и белые списки, а также автоматизация задач через встроенную систему модуля.

Время выполнения по сравнению с обычными приложениями-чистильщиками на рынке — быстрее чем ✈️. Автоматизация обеспечивается компонентом **Timed** с минимальным потреблением ресурсов — его можно просто игнорировать. Нет фоновых процессов, нет принудительной привязки к приложению, поддерживается полнофункциональный терминальный интерфейс **TUI**.

# Краткое описание функций：



## Оптимизация и очистка в один клик

Быстрая оптимизация и очистка в один клик — эффект аналогичен регулярной оптимизации. Включает очистку кэша, мусора, быструю дисковую **GC** и другое. В зависимости от настроек модуля также может выполнять очистку и классификацию файлов.



## Очистка пользовательских каталогов

Функция очистки по правилам — можно добавлять свои правила в каталог **`/data/adb/wipe_cache/CleanConfigs`**.

Настройка：

Правила оформляются в текстовом формате. В первой строке можно указать **`@/xxx`** (начиная с корня) для задания начального каталога. Каждый файл правил независим.

Один путь к файлу/каталогу на строку. Если указан начальный каталог, можно указывать только относительные пути.



## Очистка мусорных файлов и пустых папок

Очистка пустых папок во внутреннем/внешнем хранилище, кэша мультимедиа, кэша приложений и т.д.



## Очистка кэша всех приложений

Очистка кэша сторонних приложений, не включая системные. Если включена очистка кэша внешнего хранилища — очищается и он.



## Глубокая очистка файлов

Функция очистки файлов, поставляется с некоторыми встроенными конфигурациями, поддерживает пользовательские форматы файлов и внешнее хранилище.

Метод настройки：

Каталог конфигурации： **`/data/adb/wipe_cache/FileConfigs`**

Способ настройки： Создайте файл с расширением **.conf** в каталоге конфигурации. Имя файла (без расширения) будет отображаться на странице очистки как название соответствующего пункта. Впишите пользовательские расширения файлов в этот файл, разделяя пробелами или переводами строк. Строки, начинающиеся с `#`, являются комментариями.

Внутри файла укажите **`@MAX или MIN = < размер / B или BYTE / K или KB / M или MB / G или GB >`**, чтобы задать диапазон размера целевых файлов. Парсинг переопределяемый — последующие объявления заменяют предыдущие, поэтому вы можете использовать это для создания собственных правил.

Пример：

``` conf
# Это комментарий

# Это объявление указывает, что нужно классифицировать только файлы zip и 7z размером не более 1 ГБ и не менее 10 МБ
# но для iso и img ограничение по максимуму отсутствует

@MAX=1/G @MIN=10/M

zip 7z

# max -1 означает «без ограничений» (max перестаёт действовать до следующего объявления, но min продолжает действовать)

@max=-1
iso img

# Также поддерживаются KB, MB, GB &

@MIN=10/KB exe
@MIN=1/MB apk
```

Примечание：**MIN** не может быть больше **MAX**, иначе **MIN** автоматически игнорируется. Перед установкой большего значения **MIN** сбросьте **MAX**. **MAX**, **MIN** и единицы измерения **регистронезависимы** (вы уже заметили :⁠-⁠)），**поддержка чисел с плавающей точкой (дробных) отсутствует**.

Страница очистки в приложении/терминале строится динамически на основе файлов конфигурации.

Область применения： очистка файлов, классификация файлов.



## Очистка по правилам для приложений

Одна из функций очистки по правилам — очистка внутренних приватных каталогов приложений.

Настройка：

Каталог конфигурации： **`/data/adb/wipe_cache/AppCleanRules`**

Создайте в каталоге конфигурации файл с расширением **conf**. Имя файла может быть любым, но без спецсимволов и пробелов.
В первой строке укажите **`@<пакет_приложения>/<имя_приложения>`** для задания соответствующего приложения.
Каждая следующая строка — путь к папке или файлу (относительно каталога данных приложения).

Модуль автоматически найдёт каталог данных приложения по указанному пакету. Имя приложения будет отображаться в интерфейсе.

Страницы очистки в приложении/терминале строятся динамически.

Не используйте абсолютные пути, начинающиеся с **`/xxx`**, иначе очистка вызовет ошибку и этот файл правил будет пропущен.

Модуль автоматически проверяет некоторые ошибки в конфигурации.



## Очистка системного кэша

Очистка системного кэша приложений и системного кэша, а также сброс данных **MTP**-хоста (может решить проблемы с отображением списка файлов при передаче по **MTP**).



## [Beta] Анализ хранилища (NCDU)

Анализ использования каталогов хранилища – кто съел моё место?



## Автоматическая очистка

Автоматизация функций — выполняется компонентом **Timed** с крайне низким потреблением ресурсов.

### **•  Знаете ли вы？**

Вы можете использовать **Timed** для выполнения своих задач！Настройка：

Каталог конфигурации：**`/data/adb/wipe_cache/TimedConfigs`**

Создайте в этом каталоге файл с произвольным именем и расширением **.conf**, заполните и измените следующие строки (некоторые являются необязательными)：

``` conf
time=интервал/единица времени (поддерживается: M/минуты, H/часы, D/дни)
date=время последнего запуска (число-метка времени). Это необязательный параметр; если не указан, программа автоматически установит текущее время. Установите -1 для немедленного выполнения.
run=программа и аргументы для выполнения, поддерживается синтаксис Shell (передаётся в Shell для обработки)
in=время начала/время окончания (выполнять только в промежутке от X до Y часов. Необязательный параметр)
post=заголовок уведомления/текст уведомления (отправить уведомление. Необязательно, не рекомендуется для задач с интервалом в минуты)
```

Из них **time** и **run** являются обязательными полями, все **KEY** нечувствительны к регистру.
Пример：

``` conf
time=1/D
date=0
run=sync
in=0/5
post=Test Run/Запущен Sync
```

Эта конфигурация будет выполнять команду **`/system/bin/sync`** один раз в день в промежутке с **0** до **5** утра и отправлять уведомление.

## Блокировка всех обновлений и установок приложений

Блокировка установки приложений на уровне файловой системы. Не влияет на внешние хранилища — если приложение установлено на внешнем носителе, эта функция не действует.



## Фиксация внутреннего хранилища

Блокировка корневого каталога внутреннего хранилища от создания файлов/папок приложениями. Не влияет на внешние хранилища.



## Блокировка генерации кэша

Важная функция модуля — динамическое предотвращение создания кэша активными приложениями.

После включения и перезагрузки автоматически отслеживает до 5 последних активных приложений и блокирует их кэш. Можно добавлять белый список.

Файл белого списка： **`/data/adb/wipe_cache/whitelist.prop`** или через приложение **ClearBox**.

**Примечание**：Модуль использует динамическое ожидание (10с и 30с) — чтобы избежать постоянной нагрузки, а также учитывает, что некоторые приложения могут запускаться с ошибками при полной блокировке кэша. Отложенный запуск блокировки после входа в приложение — оптимальное решение.

Блокировка не очищает существующий кэш, поэтому он не становится **0**, а лишь медленно растёт. Это позволяет избежать постоянной записи/удаления мелких файлов, ограничивая лишь создание больших кэшей.

Очень низкое потребление ресурсов, автоматическая задержка при выключенном экране.

Если приложение работает некорректно — добавьте его в белый список！



## Магнит (классификация файлов в один клик)

Одним нажатием классифицирует файлы во внутреннем и нескольких внешних хранилищах. Правила общие с очисткой файлов. Поддерживается пользовательский каталог для классификации.



## Привязка каталога правил (перенаправление)

Каталог конфигурации：**`/data/adb/wipe_cache/BindConfigs`**

Создайте в этом каталоге файл с любым именем и расширением **.conf** и укажите правила привязки：

``` conf
<привязываемый_каталог> <целевой_каталог>
```

Примечание：Используйте **относительные пути** (относительно внутреннего хранилища), а не абсолютные, иначе привязка не сработает.

При записи/создании каталогов/файлов в **<привязываемый_каталог>** они будут перенаправляться в **<целевой_каталог>**.

Эта функция не работает на устройствах с **sdcardfs**, но не волнуйтесь — на **Android 12+** таких устройств практически нет.



## Оптимизация диска и приложений

Набор функций оптимизации, включая оптимизацию диска (**F2FS-GC**) и предкомпиляцию приложений (**Dexoat**).


**F2FS** — дисковая **GC**, относится к экстренной **GC**, поэтому не требует частого использования — достаточно периодического запуска.
Решение основано на работе **Coolapk@Amktiao** (используется с разрешения, спасибо автору！).

![image](https://raw.githubusercontent.com/FLYCOM-E/ClearBox/main/.Images/f2fs_gc.png)

**Dexoat** — предкомпиляция приложений для ускорения запуска. Недостаток — занимает больше места (компромисс между пространством, зарядом и скоростью).
В модуле доступны три режима: системный **Dexoat** по умолчанию, пользовательские режимы компиляции, **RESET**:

Системный **Dexoat** по умолчанию：**Android** (особенно новые версии) автоматически компилирует некоторые горячие функции в фоновом режиме. Этот режим запускает системный **Dexoat** вручную — конкретный режим и параметры определяет система.

Пользовательские режимы компиляции：поддерживаются **Speed**、**Speed-profile**、**Everything**.

**RESET**：сброс состояния компиляции.
