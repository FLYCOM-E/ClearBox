   # **ClearBox** とは？

**ClearBox** は多機能で深い、高速なクリーンボックスです。ワンクリックでデバイスの空き容量を増やし、ストレージを整理・ロックし、アプリのキャッシュ、インストールパッケージ、圧縮ファイル、ゴミ、空フォルダを削除し、キャッシュの生成を抑制し、ファイルを分類・クリアし、アプリの更新やインストールをブロックします。自動最適化・クリーン、ファイル分類機能も備え、カスタムクリーンルールやファイルクリーン/整理ルール、ホワイトリストなどを追加でき、モジュールの自動化システムを活用してカスタムタスクも追加可能です。

実行時間は市販の一般的なクリーンアプリに比べて✈️のように速く、自動化機能は非常に低消費の **Timed** コンポーネントが担当し、オーバーヘッドは無視できます。バックグラウンドプロセスはなく、アプリへの強制バインドも不要で、フル機能のターミナル **TUI** をサポートしています。

![image](https://raw.githubusercontent.com/FLYCOM-E/ClearBox/main/.Images/app_home_clean.png)

__[**Magisk**](https://github.com/topjohnwu/Magisk)、[**APatch**](https://github.com/bmax121/APatch)、[**KernelSU**](https://github.com/tiann/KernelSU) および各種フォークと互換性があります__



   # インストール方法？

   ## [**リリース版**](https://github.com/FLYCOM-E/ClearBox/releases)、[**CIビルド**](https://github.com/FLYCOM-E/ClearBox/actions) または手動ビルド：
``` shell
#（NDK を設定し、変数 $ANDROID_NDK_HOME を NDK のルートディレクトリパスに設定してください）

sudo apt install zip make

git clone https://github.com/FLYCOM-E/ClearBox
cd ClearBox/ && chmod +x *

export TARGET_API=23       #（必要に応じてターゲット API バージョンを調整してください）
export TARGET_ABI=aarch64  #（オプション：aarch64、armv7a、x86_64、riscv64）

./build.sh                 #（--build-apk：オプション：release）
```

   # 機能紹介：
   
## ワンクリック最適化＆クリーン

迅速なワンクリック最適化／クリーンを実行し、定期最適化と同等の効果を発揮します。キャッシュクリア、ゴミクリア、高速ディスク **GC** などを含み、モジュール設定に応じてファイルクリーン／分類も実行できます。



## カスタムルールクリーン

この機能はルールベースのクリーン機能で、**`/data/adb/wipe_cache/CleanConfigs`** ディレクトリに独自のクリーンルールを追加できます。

設定方法：

ルールはテキスト形式で、ルールファイルの最初の行に **`@/xxx`**（ルートディレクトリから開始）を記述して初期ディレクトリを指定できます（オプション）。各ルールファイルは独立しています。

1行に1つのファイル／ディレクトリパスを記述します。初期パスを指定した場合は、完全なパスではなく相対パス（初期ディレクトリ基準）のみを記述しても構いません。



## ゴミファイルと空フォルダのクリア

内部／外部ストレージの空フォルダ、メディアキャッシュ、アプリキャッシュなどをクリアします。



## 全アプリキャッシュのクリア

サードパーティアプリのキャッシュをクリアします（システムアプリは対象外）。外部ストレージのキャッシュクリアが有効な場合は、外部ストレージもクリアされます。



## 詳細ファイルクリーン

ファイルクリーン機能で、一部の初期設定が含まれており、カスタムファイル形式設定と外部ストレージをサポートします。

設定方法：

設定ディレクトリ： **`/data/adb/wipe_cache/FileConfigs`**

設定方法：設定ファイルディレクトリに **conf** ドキュメントファイルを作成します。ファイル名はクリーンページにクリーン項目名として表示されます。カスタムファイル拡張子をこのファイルに記述し、スペースまたは改行で区切ります。コメントはサポートされていません。

ファイル内に **`@MAX=<サイズ/B/K/M/G>`**、**`MIN=<サイズ/B/K/M/G>`** を記述して、対象ファイルのサイズ範囲を指定できます。後続の宣言は以前の宣言を上書きするため、この特性を活用して自由なルールを作成できます。

例：

``` conf
@MAX=1/G @MIN=10/M
zip 7z
@max=-1
iso img
@MIN=10/KB exe
```

この宣言は、最大 **1 G**、最小 **10 MB** の **zip**、**7z** ファイルのみを分類し、**iso**、**img** には最大サイズ制限がないことを示します。

注意：**-1** は制限なしを意味します。**MIN** は **MAX** より大きくすることはできません。そうでない場合は **MIN** は自動的に無視されます。**MAX**、**MIN** およびサイズ単位は **大文字小文字を区別しません**（お気づきでしょう :⁠-⁠)）。**浮動小数点数（小数）はサポートされていません**。

アプリ／ターミナルのクリーンページは設定ファイルに基づいて動的に構築されます。

対象範囲：ファイルクリーン、および後述のファイル分類



## アプリルールクリーン

ルールベースのクリーン機能の1つで、アプリの内部プライベートディレクトリをルールに従ってクリーンします。

設定方法：

設定ディレクトリ： **`/data/adb/wipe_cache/AppCleanRules`**

設定方法：設定ファイルディレクトリに **conf** ファイルを作成します。ファイル名は任意ですが、特殊記号やスペースを含めてはいけません。
最初の行に **`@<アプリパッケージ名>/<アプリ名>`** を記述して、ルールが適用されるアプリを指定します。
以降の各行にフォルダパスまたはファイルパスを記述します。初期ディレクトリはその **App** のデータディレクトリです。

モジュールは指定されたパッケージ名に対応するアプリデータディレクトリを自動的に検索し、アプリ名はクリーンインターフェースに表示されます。

アプリ／ターミナルのクリーンページは設定ファイルに基づいて動的に構築されます。

ルートディレクトリ **`/xxx`** で始まる絶対パスをルールにハードコードしないでください。エラーが発生し、このルールファイルはスキップされます。

モジュールは一部の設定エラーを自動的にチェックします。



## システムキャッシュのクリア

システムアプリのキャッシュ、システムキャッシュをクリアし、**MTP** ホストデータもクリアします（**MTP** ファイル転送時のファイルリスト表示異常を解決できます）。



## [Beta] ストレージ分析（NCDU）

ストレージディレクトリの使用量を分析します。誰が私のストレージを消費しているのでしょう？



## 自動クリーン

機能の自動化は、**Timed** コンポーネントによって超低消費電力で実行されます。

![image](https://raw.githubusercontent.com/FLYCOM-E/ClearBox/main/.Images/auto_clean.png)

### **•  知っていますか？**

このモジュールの **Timed** を利用してカスタムタスクを実行できます！以下のように設定してください：

設定ディレクトリ：**`/data/adb/wipe_cache/TimedConfigs`**

このディレクトリに任意の名前の **.conf** ファイルを作成し、以下の行を記述・編集します（一部はオプション）：

``` conf
time=間隔時間/時間単位（現在サポート：M/分、H/時、D/日）
date=前回実行時刻（タイムスタンプ数値）。オプションのパラメータで、未記入の場合はプログラムが自動的に現在時刻を設定します。-1 に設定すると即時実行されます。
run=実行するプログラムと引数。Shell 構文をサポート（Shell で解析）
in=開始時間/終了時間（X時からY時の間のみ実行。オプション）
post=通知タイトル/通知内容（通知を送信。オプション。分単位のタスクには推奨しません）
```

**time** と **run** は必須項目です。すべての **KEY** は大文字小文字を区別しません。
例：

``` conf
time=1/D
date=0
run=sync
in=0/5
post=Test Run/Sync が実行されました
```

上記設定は毎日午前 **0～5** 時の間に **`/system/bin/sync`** コマンドを1回実行し、通知を1件送信します。

![image](https://raw.githubusercontent.com/FLYCOM-E/ClearBox/main/.Images/timed_notification.png)



## 全アプリの更新/インストールをブロック

名前の通り、ファイルシステムレベルでアプリのインストールを強制的にブロックします。拡張ストレージは対象外のため、アプリが外部ストレージにインストールされている場合はこの機能は無効です。



## 内部ストレージ固定機能

名前の通り、内部ストレージのルートディレクトリレイアウトをロックし、アプリが勝手にファイル／フォルダを作成するのを防ぎます。拡張ストレージは対象外です。



## キャッシュ生成ブロック機能

このモジュールの重要な機能で、フォアグラウンドアプリのキャッシュ生成を動的にブロックします。

この機能を有効にして再起動すると、最近のフォアグラウンドアプリ5つを自動的にキャッシュし、キャッシュをブロックします。ホワイトリストをカスタマイズして追加できます。

ホワイトリストの場所： **`/data/adb/wipe_cache/whitelist.prop`** またはモジュール **ClearBox** アプリ内で追加できます。

**その他**：モジュールは動的待機更新方式（10秒および30秒）を採用し、継続的なリソース消費を避けると同時に、一部のアプリはキャッシュブロック状態で起動すると異常が発生する可能性があるため、アプリ起動後に遅延してキャッシュをブロックするのが最適解です。

キャッシュブロックはアプリのキャッシュを削除しないため、アプリのキャッシュが **0** になることはなく、徐々に増加します。これにより、頻繁な小ファイル消去を避け、大きなキャッシュの生成のみを制限します。

超低消費電力、画面オフ時に自動的に遅延実行します。

一部のアプリで異常が発生した場合は、ホワイトリストに追加してください。



## マグネット（ワンクリックファイル分類）

内部および複数の外部ストレージのファイルをワンクリックで分類します。ルールはファイルクリーンと共通で、カスタム分類ディレクトリをサポートします。



## ルールディレクトリバインド（リダイレクト）

設定ディレクトリ：**`/data/adb/wipe_cache/BindConfigs`**

このディレクトリに任意の名前の **.conf** ファイルを作成し、カスタムマウントルールを記述します：

``` conf
<バインドディレクトリ> <ターゲットディレクトリ>
```

注意：**絶対パス** ではなく、**内部ストレージ相対パス** を記述してください。そうしないとマウントに失敗します。

**<バインドディレクトリ>** 内にディレクトリ/ファイルを書き込むか作成すると、**<ターゲットディレクトリ>** にリダイレクトされます。

この機能は **sdcardfs** を使用しているデバイスでは現在動作しませんが、**Android 12+** ではほとんどのデバイスが sdcardfs を使用していないため、ご安心ください。



## ディスク＆アプリ最適化

ディスク最適化（**f2fs-GC**）および **Dexoat**（アプリ事前コンパイル）機能を含む最適化機能セットです。


**F2fs** ディスク **GC** は緊急 **GC** に該当するため、頻繁に使用する必要はなく、定期的に実行すれば十分です。
このソリューションは **Coolapk@Amktiao** さんの作業に基づいており、許可を得ています。感謝します！

![image](https://raw.githubusercontent.com/FLYCOM-E/ClearBox/main/.Images/f2fs_gc.png)

**Dexoat** アプリ事前コンパイルは、アプリを事前にコンパイルして実行速度を向上させますが、ストレージ容量を消費する欠点があります（容量とバッテリーを犠牲にしてスムーズな動作を得るものです）。
モジュールは3つのモードをデフォルトで提供します：システムデフォルト **Dexoat**、カスタムコンパイルモード、**RESET**：

システムデフォルト **Dexoat**：**Android** システム（特に新しいバージョン）はアイドル時に一部のホットスポット関数を自動コンパイルして全体的な実行速度を向上させるため、モジュールはシステム **Dexoat** モードを提供します。このモードは手動でシステム **Dexoat** をトリガーするのと同じであり、モードやコンパイル項目はシステムが決定します。

カスタムコンパイルモード：このモードではコンパイルモードを手動で指定でき、現在 **Speed**、**Speed-profile**、**Everything** の3つのモードをサポートしています。

**RESET**：コンパイル状態をリセットします。
